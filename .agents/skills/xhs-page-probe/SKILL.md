# 小红书页面探针

以当前人工登录后的真实页面为第一事实。先观察并保存脱敏证据，再执行一个动作，然后重新观察；不得把旧脚本、单次截图、临时元素 ID 或一次命中的 class 当作当前页面合同。

## 开始前

1. 读取根目录 `AGENTS.md`、`spec.md` 和 `.agents/skills/puppy-dev/SKILL.md`。
2. 检查工作区、Python/Playwright 环境、当前入口和本地浏览器会话。保留 `XhsPost（人工）.py`，不得修改、迁移或删除。
3. 明确关键词、样本上限和写入边界。真实写入操作在当前账号登录会话的权限范围内执行，系统不限制目标笔记的归属关系。
4. 把截图、HTML、页面文本和浏览器资料放入 Git 忽略的 `.xhs-probe/`，不得提交登录态或个人数据。

## 实时决策原则

- 专用浏览器在工作台生命周期内独立可见运行；单次页面操作结束时保留现场。手动停止浏览器或正常关闭工作台时，先暂停当前任务，再同步关闭浏览器进程。
- 每一步先保存当前视口截图并读取 DOM，再使用本轮 `probe_id` 执行一个操作，操作后重新探测。
- 页面重绘、滚动、路由或弹层状态变化后，废弃旧 `probe_id`。
- DOM 可读时以结构化页面事实为准，不通过截图猜输入值、滚动位置或控件状态。
- 工作台流程投影只消费写入脱敏证据的真实执行事件，不按计划步骤、定时器或前端推测生成进度。
- 不用固定脚本预演整条页面路径；根据本轮可见状态选择下一步。
- 出现验证码、安全校验、登录失效、频率提示或账号异常时立即停止自动操作，保留现场等待人工处理，不尝试绕过。

## 当前已验证页面事实

以下事实来自 2026-08-02 的真实登录页面，只能作为下一次探测的优先候选，使用时仍要重新验证可见性、唯一性和命中层：

- 关键词 `AI Agent` 提交后进入 `/search_result_ai`；可见笔记链接形如 `/search_result/<24位十六进制ID>`。
- 搜索区出现两个重叠 `textarea`。`搜索小红书` 对应底层，轮播 placeholder 对应当时的可见输入层；不能固定选择第一个 `textarea`，必须结合边界、可见性和 `elementFromPoint` 命中结果判断。
- 搜索结果实际滚动对象是窗口文档，不是旧 `#exploreFeeds`。
- 搜索结果使用虚拟列表，当前 DOM 卡片数量会下降；跨轮累计唯一笔记 ID，不能把当前节点数当作已加载总数。
- 连续滚动累计观察到 139 个去重笔记时仍持续增量加载，没有发现可证明的有限底部。必须报告停止原因，不能声称已滚到底。
- 整页截图会触发页面滚动监听并可能重置滚动位置；实时阶段只截当前视口，整页截图仅用于不需要保留位置的基线。
- 图片笔记详情当时使用 `/explore/<笔记ID>`；已看到详情遮罩、评论滚动区、输入区、提交、回复和点赞控件。
- 当时的优先候选为 `.note-detail-mask`、`.note-scroller`、`p.content-input`、`.btn.submit`、`.reply.icon-container` 和 `.like-wrapper`。这些是实测候选，不是永久选择器合同。
- `like-active` class 当时不能可靠表示点赞状态；结合图标渲染、计数前后变化和页面结果核验。
- 点击详情遮罩的空白区域可关闭详情。每次先通过 hit-test 确认点击点属于遮罩，再点击并验证详情消失且列表或原路由恢复；不得固定坐标。
- 已在当前账号自己的图片笔记上验证取消点赞 `17 -> 16`、恢复点赞 `16 -> 17`，以及一条回复提交后评论数 `11 -> 12`。
- 尚未真实验证视频详情、整篇笔记评论提交、验证码暂停恢复、收藏和关注；不得写成已支持。

## 浏览器与人工接管

1. 使用非无头 Playwright Chromium 和固定窗口尺寸启动专用本地资料目录。
2. 不要求用户复制 Cookie，不把 Cookie、localStorage、Authorization 或签名参数写入源码、普通日志或证据。
3. 根据页面可观察状态判断登录是否完成，不以固定等待时间代替。
4. 区分 `starting`、`waiting_login`、`probing`、`waiting_human`、`executing`、`complete`、`failed` 和 `stopped`。
5. 只使用正常浏览器能力和可见页面控件，不伪造浏览器指纹、不隐藏自动化标志、不自动处理验证码。

## 探测顺序

### 1. 登录基线

- 记录脱敏 URL、标题、viewport、主 frame、子 frame 和可见交互元素分布。
- 保存当前视口截图、脱敏 HTML、有限文本摘要和事件记录。
- 输出登录状态依据，不输出 Cookie、令牌或账号私密信息。

### 2. 关键词搜索

- 通过可见搜索框输入关键词并提交，不直接拼接未验证的搜索 URL。
- 收集所有语义候选，并逐个验证可见、可编辑、唯一和当前点击命中层。
- 提交后等待 URL 或结果集合发生可观察变化；失败时记录输入实际值、前后 URL、弹层、frame 和结果候选数量。
- URL 切换到搜索页不能单独证明搜索完成；必须等待并实际识别到相对提交前新增的搜索结果笔记链接，超时后暂停并保留旧列表、空白页或异常页面现场。

### 3. 容器发现

不要预设旧 `#exploreFeeds` 或 `.note-item`。同时检查窗口和可见可滚动元素：

- 记录 `scrollTop`、`scrollHeight`、`clientHeight` 和 `overflowY`。
- 收集笔记详情链接、最近重复祖先、唯一笔记 ID、媒体标识和可见卡片数量。
- 以结构证据和业务证据共同给候选排序；完整 class 串和固定 `nth()` 只作诊断信息。

### 4. 滚动与虚拟列表

1. 先滚动排名最高的单个候选，等待滚动指标或唯一笔记集合变化。
2. 每轮记录新增唯一笔记数，并跨轮累计 ID。
3. 没有进展时再尝试下一个候选，不同时滚动多个容器。
4. 只有有限容器已到边界、再次向下滚动无位置变化且连续多轮无新增，才能报告稳定底部。
5. 对持续增量加载的结果设定明确轮数、时长或样本上限，并报告 `limit_reached`，不得用无限循环冒充“滚到底”。

### 5. 笔记详情与评论区

- 每类只打开少量去重样本，判断详情是弹层、当前页路由还是新页面。
- 区分图片和视频笔记；只报告实际出现并验证的媒体形态，不下载或逆向媒体地址。
- 识别正文、作者、媒体、互动区、评论滚动区、评论行、输入区、回复入口和状态核验方式。
- 关闭详情时优先探测遮罩空白区；操作后确认详情消失且列表状态恢复，再处理下一篇。

## 真实写入执行

只在只读探测已经证明目标和控件后执行一个真实写入动作：

1. 基于当前可见上下文生成相关且非重复的内容，检查空内容、长度、敏感信息和语义相关性。
2. 确认当前登录账号对目标笔记具备交互权限，并在局部结构中确认目标评论行。
3. 定位输入区，填入后读取 DOM 值核对。
4. 定位提交控件并执行一次提交。
5. 点击返回后记录为已派发并进入下一动作，不轮询新增文本、输入清空、计数、Toast 或其他提交后状态。
6. 输入或点击动作抛错时停止，不自动重试同一写入。

点赞状态同样必须记录操作前后状态；单一 class 不足以证明结果。评论和回复的同步截图不进入发送路径，避免证据采集阻断业务动作。

## 完整循环的固化条件

完整任务的目标顺序可以是“搜索 -> 打开笔记 -> 评论笔记 -> 选择 1 至 3 条评论回复 -> 关闭详情 -> 下一篇”，但只有各单动作在当前页面上独立验证后才接入循环。循环仍须在每个动作后重新观察，并具备：

- 写入前交互权限检查和默认只读模式。
- 每任务与每日硬限额、最小间隔和人工可见的停止条件。
- 笔记、评论、内容和不确定结果的持久幂等键。
- AI 服务失败、页面改版、登录失效和安全校验的明确暂停状态。
- 每篇关闭详情并验证列表恢复后才进入下一篇。

探针拥有页面事实、状态、人工接管和证据；策略模块拥有 AI 内容、选题、限额和去重；执行器只接收已经通过检查的明确动作，不自行生成或改写内容。

## 证据与隐私

每次运行建立时间戳目录，使用 `summary.json`、`events.jsonl`、分阶段视口截图、脱敏 HTML 和有限文本摘要记录事实。实现完整执行器后再增加 `execution_log.jsonl`。

禁止保存 HAR 请求体、Cookie、Authorization、localStorage 值、签名参数或完整带查询参数的 URL。对证据中的 URL、输入值和可见文本做最小化与脱敏；本地证据不得进入 Git。

## 失败处理

- 元素定位、点击或等待失败时，先保存现场，再基于刚读取的页面结构最多尝试 3 种已解释的候选。
- 打开详情后无法判断形态、存在结果但无法识别滚动对象、提交结果不确定时停止当前动作，不刷新丢失现场。
- 验证码、安全校验、登录失效、频率提示、页面关闭或浏览器断开时立即进入人工接管或失败状态。

## 验证与交付

1. 运行 `python -W error -m compileall -q app.py puppy tests`。
2. 运行 `python -m pytest` 和 `python app.py --help`，确认默认审核和显式自动发送边界清楚。
3. 在真实登录页面完成一个搜索、容器发现和至少两轮有效滚动；报告关键词、累计唯一笔记数、滚动对象和停止原因。
4. 分别报告图片、视频、评论区和人工接管的已验证与未验证项，不制造测试。
5. 在目标笔记上验证单动作真实写入，并记录操作前后证据。
6. 检查 `.xhs-probe/` 已被忽略，工作区不包含登录态和探针证据。
7. 更新 skill 后运行 `skill-creator` 的 `quick_validate.py`。

交付时区分仓库静态检查、真实页面验证和未验证能力。未真实运行的页面能力不得写成已支持。
