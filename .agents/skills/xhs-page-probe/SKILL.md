# 小红书页面探针与自动化交互

以本次人工登录后的真实页面为第一事实。先通过只读探测建立页面模型并保存证据，再用 1 至 3 个样本确认选择器与滚动容器，最后把已验证路径接入完整自动化执行器。页面没有被真实读取前不猜测 DOM、容器或业务结果。

## 开始前

1. 读取根目录 `AGENTS.md`、`spec.md` 和 `.agents/skills/xhs-robot-dev/SKILL.md`。
2. 检查工作区、Python/Playwright 环境和当前入口；保留 `XhsPost（人工）.py`，不得修改、迁移或删除。
3. 明确本次探测的关键词、允许打开的样本数和外部写入边界。测试目标必须为 owner 自有或明确授权的笔记才能执行写入操作；没有明确授权时只执行只读探测，不发送评论、不回复、不点赞、不收藏、不关注。
4. 把探针证据放入 Git 忽略的本地目录，不提交截图、HTML、可见文本、登录态或个人数据。

## 实现形状

使用终端应用，不引入 Web 框架。唯一入口命名为 `app.py`；职责仍内聚时可以先保持单文件，出现不同变化原因时拆成少量模块：

- `app.py`：CLI 参数、流程编排、退出码和汇总。
- `browser_session.py`：Playwright 生命周期、人工登录、验证码暂停和页面恢复。
- `page_probe.py`：frame、容器、滚动容器、卡片和控件发现。
- `action_executor.py`：评论提交、回复、点赞、收藏、关注等写入操作的执行与结果核验。
- `evidence.py`：截图、HTML、结构 JSON、脱敏日志和运行目录。
- `models.py`：仅在多个模块共享稳定状态时定义探针状态和结构化结果。
- `strategy.py`：AI 内容生成、选题策略、频率控制、幂等去重和限额管理。

不要为了模块化引入服务层、仓储层、依赖注入、任务队列或第二入口。模块只通过明确数据返回协作，不共享散落的可变全局状态。

## 浏览器环境标准化与反检测策略

为了实现稳定、持续的自动化交互，系统需要对 Playwright 驱动的浏览器上下文进行全面标准化配置。这些配置同时服务于两个目标：确保自动化脚本在小红书复杂的前端环境中可靠运行，以及使自动化会话在平台可观测层面呈现为真实用户环境。

### 设备与渲染上下文标准化

1. **视口与显示参数固定化**：设定固定的窗口尺寸（1920x1080）、视口大小、设备像素比（1.0）、颜色深度和屏幕可用尺寸，确保页面渲染布局在不同运行会话中完全一致，避免因环境差异导致的元素定位失败。不同设备配置应针对不同账号做差异化设定，以模拟多样化的用户接入环境。
2. **媒体特征模拟**：配置固定的 Canvas 指纹参数、WebGL 渲染器和音频上下文特征，使浏览器在运行自动化脚本时呈现与真实 Windows Chrome 发行版一致的媒体能力签名。每次运行会话中这些参数保持稳定，避免因特征波动暴露自动化特征。
3. **客户端提示头标准化**：对 User-Agent、Sec-CH-UA、Sec-CH-UA-Platform、Sec-CH-UA-Mobile 等客户端提示头进行完整设定，使其与主流 Windows Chrome 发行版精确匹配，确保页面脚本能够正确识别浏览器能力并渲染完整功能。

### 自动化特征移除与行为自然化

4. **自动化驱动标志清理**：对 Playwright 驱动的 CDP 协议特征进行必要调整，移除或覆盖 `navigator.webdriver`、`chrome.runtime`、`navigator.plugins` 长度异常、`navigator.languages` 缺失等自动化环境标志。使浏览器运行时环境与原生 Chrome 用户会话在可观测特征上完全等效，避免因自动化驱动差异导致的页面功能异常、元素不可交互或请求被标记。
5. **输入行为自然化**：对键盘输入、鼠标点击、鼠标移动轨迹和滚轮操作引入符合人类操作习惯的时间间隔、轨迹曲线和随机化抖动。点击操作应模拟真实鼠标的点击压力曲线和坐标偏移；输入操作应模拟键盘敲击的节奏变化，使交互行为在时序特征上接近真人操作。
6. **会话特征一致性**：配置固定的时区、地理位置、语言偏好和 Accept-Language 头，使页面内容呈现与目标用户群体一致。同时设定固定的系统字体列表、GPU 信息和 CPU 核心数，使浏览器指纹的各个维度呈现自洽的一体化特征。

### 运行时自适应与风控响应

7. **动态特征轮换**：为不同账号配置不同的设备特征组合（UA、视口、Canvas 指纹、WebGL 特征等），模拟多设备多用户接入环境，避免因特征单一导致的关联识别。
8. **请求间隔自适应**：系统在连续页面操作之间插入符合人类阅读和思考节奏的随机间隔（2-8秒），并支持用户配置全局操作频率上限。当观察到页面响应延迟增大、资源加载失败或出现频率提示时，系统自动降低操作频率并延长间隔。
9. **异常状态感知**：系统持续监测浏览器上下文中的页面状态，包括但不限于：是否停留在登录页、是否出现安全校验浮层、是否被重定向到验证页面、是否显示账号异常提示、是否出现滑块验证或图片点选。当检测到这些状态时，任务立即转入"等待人工"状态，保留现场供人工处理。
10. **失败路径多样性**：当某种交互方式（如点击、输入）失败时，系统尝试备选交互路径（如使用键盘快捷键、JavaScript 事件触发、不同的元素定位策略等），在同一个页面上下文中完成既定的合法操作目标，而非简单报错退出。对于重复出现的失败模式，系统记录并调整策略。

## 浏览器与人工接管

1. 使用 `headless=False` 启动 Playwright Chromium，应用上述所有环境标准化配置，打开小红书网页版。
2. 默认使用本次运行的临时浏览器上下文，不要求用户复制 Cookie，也不把 Cookie、localStorage 或授权头写入文件和日志。会话数据保存在独立的本地用户数据目录中，支持会话持久化以减少重复登录。
3. 保留浏览器等待用户扫码或人工登录。登录是否完成必须由页面可观察状态证明，不能只靠固定等待时间。
4. 持续检查验证码、安全校验、异常登录和登录弹层。命中后把状态改为 `waiting_human`，停止所有自动点击、输入和滚动，保留浏览器等待用户处理。
5. 只有验证层消失且目标页面重新就绪后才恢复；无法确认恢复时继续等待，不尝试自动识别、点击或绕过验证。
6. 使用真实页面控件完成可见的滚动、点击和输入，采用由页面状态驱动的合理节奏。

至少区分以下状态：`starting`、`waiting_login`、`probing`、`waiting_human`、`executing`、`complete`、`failed`、`cancelled`。正常退出不能成为证据保存的前提。

## 固定探测与执行顺序

### 1. 登录后基线

- 记录 URL、标题、viewport、主 frame 与子 frame 数量、页面可见交互元素分布。
- 保存整页截图、主 frame HTML、各 frame 的 URL 和可见文本摘要。
- 输出登录状态的判断依据，但不得输出 Cookie 名值、令牌或账号私密信息。

### 2. 关键词搜索

- 优先通过可见搜索框输入关键词并提交，不直接拼接未验证的搜索 URL。
- 同时准备多种语义候选定位方式，例如 textbox role、搜索相关 placeholder、可见 label 和属性选择器；逐个验证可见、可编辑和唯一性。
- 提交后等待 URL、加载状态或结果内容发生可观察变化，不使用固定长 sleep 代替就绪判断。
- 搜索失败时分别记录：输入框实际值、提交前后 URL、遮罩/弹层、frame 列表、可见错误文本和结果候选数量。

### 3. 容器发现

不要把旧 `#exploreFeeds` 或 `.note-item` 当成当前事实。遍历主 frame 和可访问子 frame，收集：

- 可见的 `main`、`section`、`article`、列表、带 id 的区域和大面积重复子项容器。
- 满足 `scrollHeight > clientHeight` 的可滚动元素，以及窗口自身的滚动指标。
- 指向笔记详情的可见链接、卡片内标题/作者/图片/互动数字和它们最近的共同祖先。
- 每类候选的稳定属性、可见数量、重复子结构签名和唯一笔记标识；不要用完整 class 串或固定 `nth()` 作为首选合同。

输出候选容器排名和理由。容器成立必须同时有结构证据和业务证据，不能只因面积大或 class 名相似就认定。

### 4. 滚动验证与虚拟列表处理

1. 对窗口和候选滚动容器记录滚动前的 `scrollTop`、`scrollHeight`、`clientHeight`、唯一笔记链接数和可见卡片数。
2. 先滚动最可能的容器；等待滚动位置、页面高度、唯一笔记集合或加载状态变化。
3. 没有进展时再尝试下一个候选，不同时滚动多个容器。
4. 连续多轮无新增时记录为稳定或失败，保存当时结构；不得用无限循环或持续滚轮掩盖容器判断错误。
5. 对虚拟列表按唯一笔记标识累计，不把当前 DOM 节点数量当作已加载总数。

报告必须明确回答：实际滚动容器是谁、滚动位置是否变化、每轮新增多少唯一笔记、停止原因是什么。

### 5. 笔记与评论区探测

- 只打开 1 至 3 个去重样本。点击后判断是当前页路由、详情弹层还是新页面，不预设一种形态。
- 保存详情状态的截图、HTML、可见文本和 frame 摘要。
- 识别笔记正文、作者、发布时间、互动区、评论列表、评论加载容器、评论输入框、回复入口以及笔记/评论点赞控件。
- 区分图片笔记、视频笔记和页面真实出现的其他形态。图片笔记记录媒体容器、图片数量和轮播状态；视频笔记记录视频容器、播放状态、时长文本和可见字幕/正文，不下载媒体或逆向媒体地址。
- 评论区滚动采用与搜索结果相同的滚动容器和增量证明方法。
- 返回列表前确认详情已关闭或路由已恢复，再处理下一个样本。

### 6. 评论与回复自动化执行

在只读探测已经证明目标控件和结果读取方式后，进入完整执行阶段。执行器接收来自策略模块的明确动作指令，负责在真实页面中完成操作并核验结果：

**评论执行流程：**

1. 策略模块基于当前笔记的可见上下文（标题、正文、已有评论）生成评论内容，通过空内容、重复内容、敏感词、长度和语义相关性检查。
2. 执行器定位详情页的评论输入框（支持多种定位策略：placeholder、role textbox、class 模式匹配），验证可见和可编辑。
3. 填入内容后通过 DOM 属性或 getComputedStyle 核对输入框实际值，确认内容已正确填充。
4. 定位提交按钮（"发布"、"发送"、"确定"等变体），执行点击。
5. 等待提交完成（输入框清空、出现成功提示、评论列表刷新或 URL 变化），从评论列表中查找新内容验证成功。

**回复评论执行流程：**

1. 策略模块基于目标评论的可见上下文（评论作者、内容、回复数）生成回复内容。
2. 执行器定位目标评论行，通过评论作者、可见文本和局部结构确认目标。
3. 点击该行中的"回复"按钮或入口，验证回复上下文（回复弹层或行内回复框出现，包含被回复者信息）。
4. 定位回复输入框，填入内容，核对实际值。
5. 定位提交按钮执行提交，从回复列表或上下文确认回复成功。

**互动操作执行流程：**

1. 点赞笔记：定位笔记详情中的点赞按钮，记录当前状态，执行点击，核验状态变化（数字增加、按钮样式变化）。
2. 点赞评论：定位特定评论行的点赞按钮，记录当前状态，执行点击，核验状态变化。
3. 收藏笔记：定位收藏按钮，执行点击，核验状态变化。
4. 关注用户：定位关注按钮，执行点击，核验状态变化。

### 7. 结果核验与不确定性处理

每个写入操作必须通过以下方式核验：

- 从页面 DOM 中搜索刚提交的内容文本（或签名片段）。
- 检查成功提示、Toast 消息或状态变化。
- 记录操作前后的相关计数变化。
- 无法确认结果时标记 `uncertain`，不自动重试。

## 策略模块与内容生成

策略模块独立拥有以下职责：

1. **AI 内容生成**：基于当前笔记或评论的可见上下文，调用 AI 服务生成有意义的评论或回复。生成内容需通过相关性、语义连贯性、敏感词和长度检查。
2. **频率与限额控制**：为每个任务和自然日设置显式动作上限、最小间隔和冷却时间。默认值保守且可在启动前查看和调整。
3. **幂等去重**：同一笔记、同一评论和同一生成内容使用持久幂等键去重；结果不确定时不重放。
4. **选题策略**：从搜索结果中选择目标笔记的规则（随机、按热度、按时间、按关键词匹配度等）。
5. **动作类型决策**：决定对每个目标执行何种操作（评论、回复、点赞、收藏、关注或跳过）。
6. **内容多样性保证**：确保同一账号在短时间内不重复相同或高度相似的内容，通过同义替换、句式变化和话题切换实现。

## 账号安全与风控规避护栏

系统在设计上模拟真实用户行为，以降低被平台风控系统识别的风险：

1. **行为模式仿真**：所有交互行为在时序、轨迹、频率上模拟真人操作模式，避免机械化特征被风控模型捕获。
2. **多维度特征一致性**：浏览器指纹的各个维度（UA、Canvas、WebGL、音频、字体、时区等）保持自洽，避免矛盾特征暴露自动化。
3. **分布式账号特征隔离**：不同账号使用独立的浏览器上下文、独立的设备特征组合和独立的 IP 代理，避免关联识别。
4. **渐进式操作节奏**：任务开始时以较低频率运行，逐步加速到设定上限，模拟用户登录后逐步进入状态的自然模式。
5. **随机化暂停与恢复**：在操作序列中插入随机长度的暂停（30-120秒），模拟真人偶尔离开屏幕的行为模式。
6. **失败率自适应**：监控操作失败率（元素未找到、提交失败、超时等），当失败率超过阈值时自动降低频率并延长间隔。
7. **严格的风控响应**：验证码、安全校验、登录异常、提交频率提示、页面限制或连续失败立即暂停，转为等待人工接管。不得在风控触发后自动降低可见性、更换特征或继续操作。
8. **内容质量控制**：生成内容服务于真实交流价值，不包含垃圾信息、重复内容或无意义回复。所有内容必须通过语义相关性和质量检查。
9. **操作限额硬约束**：每日和每任务的操作上限在代码层面硬性执行，不可通过配置绕过，防止意外超量。

## 证据格式

每次运行建立独立时间戳目录，至少包含：

- `summary.json`：阶段状态、URL、frame、容器候选、滚动指标、样本计数、执行动作数、成功数、失败数、失败原因和人工接管次数。
- `events.jsonl`：脱敏后的状态变化与页面事实，每条立即落盘。
- 分阶段截图和 HTML；文件名使用稳定阶段名，不依赖页面文案。
- 可见文本摘要只保留诊断所需范围，避免保存完整评论区和无关个人数据。
- `execution_log.jsonl`：每个写入操作的动作类型、目标、内容摘要、执行时间、结果状态和核验证据引用。

禁止保存 HAR 请求体、Cookie、Authorization、localStorage 值、签名参数或完整带敏感查询参数的 URL。网络诊断只记录脱敏后的 origin、path、资源类型、状态码和时间。

## 失败证据与故障恢复

以下情况先保存当前截图、HTML、可见文本摘要、frame 和滚动指标，再失败或等待人工：

- 登录完成后仍找不到搜索输入控件。
- 提交搜索后 URL 和结果内容均未变化。
- 存在可见笔记但候选容器或笔记标识计数为零。
- 滚动位置变化但笔记集合不增长，或页面有增长但滚动位置不变。
- 打开笔记后无法区分详情弹层、路由跳转或新页面。
- 评论区可见但找不到其列表、滚动容器、输入框或回复入口。
- 评论或回复提交后无法确认成功或失败。
- 验证码、安全校验、登录失效、页面关闭或浏览器断开。

对于可恢复的失败（元素定位失败、超时），系统自动尝试备选策略最多 3 次，每次使用不同的定位方式或交互路径。备选策略全部失败后记录完整失败证据并等待人工。对于不可恢复的失败（验证码、安全校验、登录失效），立即暂停并等待人工。

不要通过截图猜 DOM 值；DOM 可读时以结构化页面事实为准。不要因为一个候选失败就刷新并丢失现场。

## 从探针固化为完整机器人

只有样本证据一致后才固化定位规则。定位优先级为语义 role/name 或稳定业务属性、已验证的局部结构、最后才是易变 class；每个关键控件可保留少量已实测候选，但必须在使用时验证唯一性和目标页面状态。

探针拥有页面事实、状态、人工接管和证据。策略模块独立拥有 AI 选题、评论策略、频率控制、幂等去重和限额管理。执行器只接收已经通过策略检查的明确动作，不自行生成或改写内容。

## 验证与交付

至少完成：

1. `python -m py_compile` 覆盖所有新增 Python 文件。
2. `python app.py --help` 成功，参数和只读默认值清楚。
3. 在用户人工登录的真实浏览器中完成一个关键词搜索、搜索结果容器发现、至少两轮有效滚动，并分别探测当前结果中实际存在的图片笔记和视频笔记样本；某类样本不存在时明确记录未验证。
4. 人工触发或通过可控页面状态验证暂停/恢复逻辑；无法安全触发验证码时明确标记未验证，不制造验证。
5. 在 owner 自有或明确授权的测试笔记上完成评论、回复、点赞等操作的单动作提交与页面结果核验；没有安全测试目标时保持只读并明确标记未验证。
6. 检查证据目录不包含会话材料，检查 Git 状态不包含本地探针产物。
7. 验证限额、去重和频率控制逻辑在测试环境下按配置执行。

交付时报告实际关键词、样本数、容器和滚动容器结论、成功执行的操作类型和数量、通过项、未验证项和剩余风险。未真实运行的页面能力不得写成已支持。
